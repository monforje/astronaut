# 06. Пакет для ДТ и сверка перед подачей: как это для клиента

> [← Юзкейсы по шагам](../README.md) · [Фейк-данные](../fake-data.md) · [Как это для клиента](user-view.md) · [Что нужно сделать](tasks.md) · [Бизнес-логика](business-logic.md)

Кто: менеджер ВЭД, брокер. Что получает: данные для программы брокера без второго набора и сверку ДТ с остальными документами до подачи. Подаёт декларацию брокер в своей программе, мы в ФТС не ходим.

> Формат обмена с Альтой не проверен. В моках показываем выгрузку файлом, которую брокер загружает у себя.

## Шаги

1. Когда все документы по грузу сверены, в карточке появляется кнопка «Подготовить пакет для брокера».
2. Менеджер выбирает брокера (из Справочника) и нажимает «Подготовить». Система собирает данные из карточки: контрагенты, позиции, вес, стоимость, документы.
3. Пакет можно скачать файлом или отправить брокеру. Брокер загружает его в свою программу.
4. Когда брокер подготовил ДТ, он или менеджер загружает её в карточку. Система сверяет ДТ с инвойсом, упаковочным листом, коносаментом и ПИ.
5. Результат сверки: «стоимость совпала», «количество в позиции 3 расходится», «наименование: смысловое соответствие». Решение принимает декларант (брокер), мы только показываем.
6. После выпуска в ленте груза появляется событие «выпущен таможней» (юзкейс 10).

## Экраны

| Экран | Зачем | Главное действие |
|---|---|---|
| Пакет для брокера | Собрать и отправить данные | «Подготовить» |
| Сверка ДТ | Показать расхождения перед подачей | «Отправить брокеру замечания» |

## Когда что-то не так

| Ситуация | Что видит человек |
|---|---|
| В карточке не хватает сведений | «Для пакета нужно заполнить: …» |
| ДТ в формате, который не читаем | «Не удалось прочитать ДТ. Загрузите PDF или XML» `[TODO: какие форматы]` |
| Брокер не отвечает | Статус «пакет отправлен, ответа нет», напоминание |

## Тексты

Решение по ДТ всегда за декларантом. В тексте не пишем «исправьте», а «обратите внимание».
