# 11. Доступ к данным для других сервисов: как это для клиента

> [← Юзкейсы по шагам](../README.md) · [Фейк-данные](../fake-data.md) · [Как это для клиента](user-view.md) · [Что нужно сделать](tasks.md) · [Бизнес-логика](business-logic.md)

Кто: админ. Что получает: данные 1С доступны сайту, отчётам и кабинету в нормальном виде, без отдельной выгрузки под каждый сервис. В питче звучит на минуту, продаётся не первой.

## Шаги

1. Админ открывает «Доступ к данным» и видит, какие данные доступны: клиенты, грузы, контейнеры, документы.
2. Включает «Витрину в PostgreSQL»: система показывает адрес и логин для BI и аналитиков.
3. Включает «Data API»: создаёт ключ, выбирает права (например, «клиент видит только свои грузы»), получает автодокументацию.
4. Видит, когда данные обновлялись в последний раз.
5. Может создать подписку на событие: «груз выпущен → отправить на адрес».

## Страницы

| Страница | Зачем | Главное действие |
|---|---|---|
| Доступ к данным | Что включено, адрес, статус обновления | «Включить» |
| Ключи API | Создать ключ с правами и лимитом | «Создать ключ» |
| Документация API | Что можно спросить | открыть |
| События | Подписка на изменения | «Добавить подписку» |

## Когда что-то не так

| Ситуация | Что человек узнаёт и что может сделать |
|---|---|
| Данные давно не обновлялись | «Последнее обновление N часов назад. Проверьте обмен с 1С» и переход в мониторинг |
| Ключ скомпрометирован | Ключ можно сразу «Отозвать» |
