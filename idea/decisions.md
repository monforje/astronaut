# Решения

| Дата | Решение | Почему |
|---|---|---|
| 2026-10-31 | Старые материалы перенесены в `begining/`, новая работа идёт в `idea/` | Начинаем аудит и пересборку продукта с чистого листа, опираясь на старое как на исходник |
| 2026-11-01 | ЦА для MVP — логистические компании Владивостока и Дальнего Востока (транзит, экспедирование) | Есть прямой выход на эти компании и возможность питчить им лично |
| 2026-11-01 | Итоговый продукт собирается из блоков, каждый из которых позже можно продавать отдельно. Исходный список: шина с коннекторами и API-обёрткой, платформа отказоустойчивости, маппинг и MDM/НСИ, AI и ML | Строим на продуктах поменьше; блоки потом становятся отдельными услугами |
| 2026-11-01 | Модель FROM → BY → TO из `begining/` сохраняется как основа слоя движения данных | Она уже описывает и коннекторы, и способы строить потоки |
| 2026-11-01 | Слой движения данных включает подготовку данных из 1С, ERP и CRM для других сервисов: витрина в SQL, Data API, события, выгрузки | Смысл не только перенести из А в Б, но и дать сервисам нормальный доступ к данным |
| 2026-11-01 | AI — сквозной агент с доступом ко всей платформе: по просьбе делает коннекторы, потоки, золотые записи, сверки. Заменяет старое правило «AI только предлагает» из `begining/` | Пользователь не тыкает кнопки, а просит. Безопасность через права пользователя, выкат в Продуктив, аудит и откат |
| 2026-11-01 | Питч и материалы для продаж пока не делаем. Сначала разбор конкурентов и закрытие открытых вопросов, потом пользователь читает все документы и правит, и только после финальной версии переходим к продажам | Хочет сначала сам проверить и согласовать всё написанное |
| 2026-11-01 | Первый шаг: база из 20–30 логистических компаний Владивостока с публичными контактами и боли по открытым источникам, под них примеряем решение без интервью | Быстро понять ЦА до встреч; интервью и питчи пойдут уже по этой базе |
