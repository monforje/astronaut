## Рынок и ЦА

| Дата | Решение | Почему | Статус |
|---|---|---|---|
| 2026-11-01 | Позиционирование — «платформа интеграции данных для логистических и транспортных компаний». Определяем себя через отрасль, а не через размер клиента | «Для среднего бизнеса» отталкивает крупных (Транзит, FESCO, ВСК) и ничего не говорит экспедитору | решено |
| 2026-11-01 | Размер клиента определяет пакет: «Старт» для экспедиторов на 20–200 человек (это MVP), «Корпоративный» для крупных компаний, линий, портов и терминалов ([fit.md](audience/fit.md#пакеты-старт-и-корпоративный)) | Одна платформа, разные требования: скорость запуска против своих серверов, отказоустойчивости и внедрения | решено |
| 2026-11-01 | ЦА для MVP — экспедиторы морского импорта Владивостока на «Старте»: ТИС, ВЛ Лоджистик, Фарес, Логист, Орион-Экспресс ([fit.md](audience/fit.md#кому-идём-в-первую-очередь)) | Есть прямой выход на компании; их процесс — ровно наш сценарий | гипотеза |
| 2026-11-01 | Терминалы и порты — корпоративные клиенты с болью «API для клиентов вместо кабинетов», а не «другой продукт». Берём после первого кейса и понятного пути в реестр ПО | Сильная боль П3; заодно решается доступ к данным для трекинга | гипотеза |
| 2026-11-01 | Первый шаг — база компаний с публичными контактами и боли по открытым источникам, под них примеряем решение | Понять ЦА до встреч | решено |
| 2026-11-01 | Главное отличие — сверка инвойса, упаковочного листа, коносамента, ПИ, ДТ и ЭТрН по карточке груза ([differentiators.md](product/differentiators.md)) | По открытым источникам такого продукта не нашли | гипотеза |

| 2026-11-01 | Сверка: сравнение полей и допуски — обычный код по [матрице сверки](product/logistics-flow.md#матрица-сверки-черновик), LLM только для нечётких наименований и объяснений | Токенизация ломает сверку названий в LLM; ложные срабатывания недопустимы | решено |
| 2026-11-01 | ЭПД подписывает человек (КЭП, МЧД) в кабинете оператора; ключи подписи мы не храним | Проще юридически и по безопасности | решено |

## AI-агент

| Дата | Решение | Почему | Статус |
|---|---|---|---|
| 2026-11-01 | AI — сквозной агент внутри приложения клиента: экран-чат как ChatGPT и боковая панель. Через MCP видит всю платформу и все данные, работает в песочнице. Образец — ассистенты Yandex Cloud и Cloud.ru. Заменяет старое правило «AI только предлагает» | Пользователь просит, а не тыкает кнопки | решено |
| 2026-11-01 | Анализ данных и прикладные функции — платные расширения над агентом: распознавание, сверка, ТН ВЭД, аналитика, качество данных, агент для клиентов экспедитора | Отдельные надстройки, которые можно продавать по одной | решено |
| 2026-11-01 | Агент меняет Продуктив только через подтверждение человека. Без подтверждения — чтение, отчёты, перезапуск недоставленных обменов. Повторная отправка ЭПД — всегда с подтверждением | Баланс скорости и безопасности; дубль юридически значимого документа недопустим | решено |
| 2026-11-01 | При разборе внешних документов у агента только инструменты чтения, без доступа к другим клиентам | Защита от prompt injection через PDF | решено |
| 2026-11-01 | Модель может видеть все данные, но через анонимизацию, маскирование, токенизацию и гардрейлы. Это снижает риск, но не заменяет юридическую оценку по 152-ФЗ | Без данных не работают распознавание и золотая запись | решено |
| 2026-11-01 | Провайдер модели выбирает клиент: адаптер к любому OpenAI-совместимому API (OpenRouter, YandexGPT, GigaChat, локальная) | Почти все провайдеры совместимы; клиентам с ограничениями — российская или локальная модель | решено |
| 2026-11-01 | Агент учится на решениях людей только внутри одного клиента | Решения клиента — его конфиденциальные данные | решено |
