# Термины

Простое объяснение, затем пример из логистики. По алфавиту: сначала латиница, потом кириллица.

| Термин | Что значит | Пример в логистике |
|---|---|---|
| **API** | «Розетка» системы, через которую другая программа может автоматически забирать или отправлять данные без человека. | Сайт морской линии отдаёт статус контейнера по API, и он сам подтягивается в систему экспедитора. |
| **CRM** | Система работы с клиентами: заявки, сделки, переписка, история общения, воронка продаж. Примеры: Битрикс24, amoCRM. | Менеджер ведёт клиента от первой заявки «привезти 3 контейнера из Шанхая» до подписанного договора. |
| **CDC** | Change Data Capture: забирать из базы данных только изменения, сразу как они произошли, а не перечитывать всё целиком. | Новая заявка в базе сразу уходит в шину, без выгрузки раз в час. |
| **EDI** | Стандартизированный обмен документами между компаниями в машиночитаемом виде (не PDF глазами, а структура). | Линия присылает букинг и коносамент в формате, который система читает сама. |
| **ERP** | Большая система учёта всего предприятия: финансы, закупки, склад, кадры. В России чаще всего это 1С (1С:ERP, 1С:УТ, 1С:Бухгалтерия). | В 1С ведутся счета клиентам, расходы на фрахт, взаиморасчёты с перевозчиками. |
| **ESB (шина данных)** | Центральный «почтамт» между системами: каждая система подключается один раз к шине, а шина сама разносит данные кому нужно. Альтернатива — каждая система соединена с каждой напрямую. | Новый заказ из CRM через шину сразу попадает в 1С, в WMS и в TMS. |
| **ETL** | Выгрузить данные из систем, привести к единому виду и загрузить в хранилище для отчётов. Работает пакетами, обычно по расписанию. | Каждую ночь собирать данные о перевозках из всех систем в одну таблицу для отчёта директору. |
| **MDM (мастер-данные)** | Управление главными справочниками компании: контрагенты, номенклатура, адреса, договоры. Цель — чтобы одна сущность везде была записана одинаково. | «ООО Ромашка», «Ромашка ООО» и «Ромашка» с одним ИНН — это один клиент, а не три. |
| **OCR / распознавание документов** | Превращение скана или PDF в структурированные данные: поля, таблицы, суммы. | Китайский инвойс в PDF за минуту превращается в строки с наименованием, весом и ценой. |
| **SDK** | Набор библиотек для разработчика, чтобы работать с платформой из своего кода. | Разработчик описывает поток на Python и хранит его в git. |
| **TEU** | Условная единица контейнерного груза: один 20-футовый контейнер. 40-футовый = 2 TEU. | «Импорт через порты ДФО — 621 тыс. TEU за 7 месяцев». |
| **Terraform** | Инструмент, в котором инфраструктуру и настройки описывают файлами, а не кликами. Можно хранить в git, сравнивать и откатывать. | Все подключения и потоки клиента описаны в файлах и выкатываются одной командой. |
| **TOS** | Система управления контейнерным терминалом: где стоит контейнер, когда его выгрузили, кто заберёт. | ВМТП ведёт контейнеры в своей TOS, экспедитор узнаёт статус через её кабинет. |
| **TMS** | Система управления перевозками: планирование рейсов, выбор перевозчика, маршруты, статусы в пути, расчёт стоимости. | Диспетчер видит, где фура с контейнером, когда она будет на складе и сколько стоит рейс. |
| **WMS** | Система управления складом: приёмка, ячейки хранения, сборка, отгрузка, инвентаризация. | На СВХ видно, в какой ячейке лежит груз клиента и что его можно выдавать после выпуска таможней. |
| **1С** | Российская платформа учётных программ, стандарт де-факто для бухгалтерии и учёта. Не одна программа, а семейство «конфигураций» (Бухгалтерия, УТ, ERP, Управление автотранспортом и др.) с возможностью дописывать под себя. | В экспедиторской компании в 1С учитывают сделки, выставляют счета, считают маржу по перевозке. |
| **FROM → BY → TO** | Наша модель потока данных: откуда берём (FROM), чем и как строим поток (BY: конструктор, AI-агент, код, Terraform), куда кладём (TO). | FROM 1С → BY шаблон «ЭТрН» → TO Контур. |
| **Low-code** | Сборка логики мышкой в визуальном редакторе, почти без программирования. | Аналитик рисует поток 1С → Контур и выбирает поля из списков. |
| **Витрина данных** | Копия данных в удобном виде и в отдельной базе, чтобы с ними работали отчёты и сервисы, не трогая исходную систему. | Грузы и клиенты из 1С лежат в Postgres таблицами `shipments` и `clients`, BI строит отчёты оттуда. |
| **ГИС ЭПД** | Государственная система, через которую с 01.09.2026 обязательно проходят электронные перевозочные документы. Компания работает с ней не напрямую, а через оператора (Контур, СБИС и др.). | ЭТрН на рейс от порта до склада уходит через оператора в ГИС ЭПД. |
| **ГосЛог** | Госреестр экспедиторов (с 01.03.2026) и перевозчиков (с 01.03.2027). С перевозчиком не из реестра нельзя заключать договор. | Перед заказом машины проверяем, есть ли перевозчик в ГосЛоге. |
| **ДО-1, ДО-2** | Отчёты СВХ в таможню: ДО-1 — груз принят на хранение, ДО-2 — груз выдан. Подаются электронно. | Крупный СВХ делает их сотнями в день. |
| **ДТ** | Декларация на товары: основной таможенный документ на ввоз, подаётся в ФТС в электронном виде. | Брокер подаёт ДТ на контейнер с электроникой из Китая. |
| **Золотая запись** | Итоговая «правильная» версия сущности, собранная из разных систем: лучшие поля из каждой, без дублей. Результат работы MDM. | Из 1С берём реквизиты клиента, из CRM — контактное лицо, из ЭДО — подтверждённый ИНН. Получаем одну карточку клиента на всю компанию. |
| **API-шлюз** | Единая «проходная» для API: принимает внешние запросы, проверяет ключи, ограничивает частоту и передаёт запрос нужной системе внутри. | Клиент экспедитора запрашивает статус груза через шлюз, а не лезет напрямую в 1С. |
| **Интеграция** | Настроенный автоматический обмен данными между двумя или несколькими системами. | Статус «груз выпущен таможней» сам приходит из системы брокера в CRM и уведомляет клиента. |
| **Интеграция «точка-точка»** | Каждая пара систем соединена своим отдельным обменом. При 5 системах таких связей может быть до 10, и каждую кто-то пишет и чинит отдельно. | Свой обмен 1С↔CRM, свой 1С↔склад, свой CRM↔сайт; уходит программист — никто не знает, как они работают. |
| **Наблюдаемость** | Возможность в любой момент видеть, что происходит с обменами: что прошло, что застряло, где ошибка, и получать сигнал о сбое сразу. | Обмен 1С → оператор ЭПД упал в 14:02, в 14:03 в Telegram пришло сообщение с причиной. |
| **Коннектор** | Готовый модуль подключения к конкретной системе. Чем больше готовых коннекторов, тем быстрее делается интеграция. | Коннектор к 1С, к Битрикс24, к сервису отслеживания контейнеров. |
| **НСИ** | Нормативно-справочная информация: общие справочники компании (контрагенты, номенклатура, единицы измерения, адреса, коды). По сути то же, чем занимается MDM, только российский термин. | Справочник кодов ТН ВЭД и справочник клиентов — это НСИ. |
| **Маппинг** | Правило соответствия полей между системами: что в одной системе называется так, в другой — эдак. | Поле «Грузополучатель» в TMS = поле «Контрагент» в 1С. |
| **Инвойс, упаковочный лист** | Документы поставщика: инвойс — что и почём продано, упаковочный лист — как упаковано (места, вес, объём). Основа для таможни. | Китайский поставщик присылает оба PDF-файлами. |
| **Коносамент** | Морской документ на груз: подтверждает, что линия приняла груз к перевозке, и даёт право его получить. | Без оригинала или электронного релиза коносамента контейнер в порту не выдадут. |
| **ПИ (предварительная информация)** | Сведения о товарах, которые подаются в таможню до прибытия груза. Во Владивостоке (свободный порт) обязательна. | Данные из коносамента и инвойса уходят в ФТС до прихода судна. |
| **Поручение экспедитору, экспедиторская расписка** | Поручение — клиент поручает экспедитору перевозку. Расписка — экспедитор подтверждает, что принял груз. Оба электронные (ЭПД) с 01.09.2026. | Клиент подписывает поручение в Контуре, экспедитор выдаёт расписку. |
| **СВХ** | Склад временного хранения: таможенный склад, где груз лежит до выпуска таможней. | Контейнер из Китая выгрузили на СВХ во Владивостоке и ждут оформления декларации. |
| **Транзит** | Перевозка груза через территорию/узел без остановки в нём как в конечной точке. Для Владивостока — перевалка из Азии на ЖД или авто дальше вглубь России. | Контейнер из Китая пришёл морем во Владивосток, перегружен на поезд и уехал в Москву. |
| **ТН ВЭД** | Товарная номенклатура внешнеэкономической деятельности: код товара для таможни. От кода зависят пошлины, разрешения, а теперь и проверки китайских банков. | Ошибка в коде ТН ВЭД — и платёж в Китай возвращается, а груз задерживают. |
| **ФТС** | Федеральная таможенная служба. | Выпуск груза, отчёты СВХ, декларации. |
| **ЭДО** | Электронный документооборот: юридически значимые документы (счета, акты, УПД) с электронной подписью вместо бумаги. Операторы: Диадок, СБИС, 1С-ЭДО. | Акт о выполненной перевозке подписывается клиентом в Диадоке, а не возится курьером. |
| **ЭПД** | Электронные перевозочные документы: общее название для ЭТрН, заказа-заявки, экспедиторских документов, ж/д накладной. Обязательны с 01.09.2026. | Экспедитор оформляет поручение и экспедиторскую расписку электронно. |
| **ЭТРАН** | Система РЖД для оформления ж/д перевозок: накладные, заявки, где сейчас вагон. Подключение из 1С идёт через защищённый канал ViPNet и согласуется с РЖД 1–2 месяца. | Экспедитор оформляет отправку контейнера Владивосток → Москва в ЭТРАН. |
| **ЭТрН** | Электронная транспортная накладная: электронная замена бумажной накладной на автоперевозку, оформляется через операторов и ГИС ЭПД. | Перевозчик выставляет ЭТрН на рейс от порта до склада клиента. |
