# entities

Сущности предметной области — существительные. Слайс знает, как сущность получить, что с ней можно
посчитать и как её показать «глупым» компонентом.

```
entities/<сущность>/
  index.ts                             export { ItemCard } from "./ui/item-card";
  api/use-<сущность>/use<Сущность>.ts  запросы поверх сгенерированного клиента: ключ, staleTime, enabled, перевод ошибок
  model/<модуль>/<модуль>.ts           чистые функции, константы, стор zustand + тесты
  ui/<компонент>/<Компонент>.tsx       отображение без действий, со своими состояниями загрузки и ошибки
                                       (+ .module.css, .test.tsx, index.ts в той же папке)
```

## Правила

- Имя слайса — существительное в единственном числе: `item`, `viewer`, `system`.
- Типы — из `@/shared/api` (контракт), своих DTO нет; производные типы — в `model/`.
- Хук запроса оборачивает сгенерированную функцию и ключ (`systemInfo`, `getSystemInfoQueryKey`): здесь
  `staleTime`, `enabled` и перевод «нет данных» в `null`, а не в каждом потребителе.
- Хелперы кэша рядом с запросом (`setItemCache`) — ими пользуются фичи.
- UI сущности не вызывает мутаций и не навигирует: получает данные пропсами или из своего хука.

Пример — `system/`: хук `useSystemInfo` и карточка `SystemInfoCard` с состояниями.
