# AppShell и паттерны страниц

Оболочка приложения (бренд, топбар, сайдбар, контент) и четыре паттерна страниц: cargo-экран, list-detail, настройки, дашборд. Раскладка без мёртвого места.

AppShell задаёт каркас всех экранов: слева сайдбар с брендом, сверху топбар, в остатке область страницы с полями 16 px и зазором 16. Паттерны страниц — проверенные способы заполнить область так, чтобы не оставалось пустых углов: колонки дают в сумме 12 или заполняют высоту, нижняя карточка растёт до края соседней, панели прокручиваются сами. Здесь схемы, а не реализация: блоки подписаны, пропорции взяты из макета.

- **id:** `app-shell`
- **Группа:** Навигация (`navigation`)
- **CSS-префикс:** `ds-shell`
- **Origin хореографии:** mockup (3)

## Когда использовать / не использовать

### Использовать

- Один каркас на все страницы: бренд · топбар · сайдбар · контент.
- Крошки в топбаре и страница без заголовка; ряд действий в самом содержимом.
- Сайдбар и топбар липкие, скроллится только область контента (или панели внутри неё).
- Паттерн выбирайте по задаче: список+объект → cargo; очередь → inbox; формы → settings; обзор → dashboard.
- Ряды сетки в сумме дают 12; высоты карточек в ряду равны.
- Каждый паттерн имеет состояния loading/empty/error: в области контента, не вместо оболочки.

### Не использовать

- Два уровня прокрутки на странице list-detail.
- Колонки по 3+4+4: дыра в одну колонку справа.
- Растягивать пустые карточки ради ровной сетки: пустое — это EmptyState.
- Свой каркас на отдельной странице («особый» топбар или сайдбар).
- Левая акцентная полоска на карточках и пунктах: акцент — подложка и кольцо.
- Заголовок страницы под крошками: когда крошки есть, заголовка нет.

## Анатомия

1. **Бренд** — Ячейка слева сверху: логотип и название (в rail — знак). Высота 56 px, ширина как у сайдбара, линии справа и снизу. Липкая, z-index 30.
2. **Топбар** — Ячейка сверху справа: крошки, поиск, действия. Липкая, 56 px. Вместе с брендом образует одну горизонтальную линию.
3. **Сайдбар** — Ячейка слева под брендом: липкая, высота `100vh − 56`, собственная прокрутка. Ширина 248 или 56 (rail); колонка оболочки `auto` следует за ней.
4. **Контент** — Область страницы: `minmax(0, 1fr)`, поля 16. Внутри `.page`: grid с зазором 16, `align-content: start`. Паттерн страницы выбирает раскладку внутри.

## Варианты

- **Cargo-экран: KPI + таблица + карточки** (`cargo`): Ряд из четырёх KPI, под ним split: таблица с вкладками (1fr) и стопка карточек справа шириной 340 px. Правая колонка тянется по высоте таблицы, последняя карточка («История») заполняет остаток. Когда: главный экран работы: список объектов и выбранный объект рядом. Таблица прокручивается внутри, страница — нет.
- **List-detail «inbox»** (`inbox`): Три панели 340 | 1fr | 300 на высоту окна минус шапка и поля (100vh − 56 − 32, не менее 600 px). У каждой панели свой скролл; у детали сверху заголовок с действиями, Stepper и Tabs. Когда: разбор очереди: расхождения, обращения, заявки. Нужно листать список и решать, не теряя контекст.
- **Настройки** (`settings`): Слева навигация по разделам 220 px (липкая, top 72), справа колонка карточек шириной до 1080 px: заголовок раздела, формы в 2 колонки, строки-переключатели, «опасная зона». Панель сохранения липнет к низу окна. Когда: формы и конфигурация: много независимых блоков, мало данных.
- **Дашборд** (`dash`): Сетка 12 колонок, зазор 16. Ряд KPI 3+3+3+3, график 8 + статусы 4, топ клиентов 5 + прибытия 4 + активность 3: ряд всегда даёт ровно 12, карточки в ряду одной высоты (align-items: stretch). Когда: обзор показателей: каждый блок ведёт на подробный экран.

## Состояния

### Применимые

- **Развёрнутый сайдбар** (`default`): Сайдбар 248 px, бренд с названием; контент занимает остаток.
- **Rail** (`selected`, `rail`): Сайдбар и бренд 56 px; контент шире на 192 px, колонки паттерна перестраиваются.
- **Мобильный (≤ 760)** (`other`, `mobile`): Нет сайдбара и бренда; топбар без поиска. [TODO] мобильное меню.
- **Loading** (`loading`): Оболочка уже на месте, загрузчик с брендовым знаком — в области контента. На всю страницу — только при первом входе (затухание 260 мс).
- **Empty** (`empty`): Нет данных: EmptyState по центру области с одним действием. Паттерн целиком не рисуется.
- **Error** (`error`): Ошибка загрузки страницы: плашка в области контента с «Повторить»; навигация доступна. [TODO] предложение, в макете нет страницы ошибки.

### Не применимы (с причиной)

- **Hover / Active / Focus** (`hover`): У оболочки нет: состояния принадлежат вложенным компонентам (Sidebar, Topbar, Tabs).
- **Disabled** (`disabled`): Нет: недоступный раздел — это disabled-пункт сайдбара.

## Доступность

- **Ориентиры** (`aria`): header (топбар), nav aria-label «Разделы» (сайдбар), main (контент). У навигации в настройках — свой nav aria-label «Разделы настроек».
- **Порядок фокуса** (`key`): Топбар (крошки → поиск → тема → уведомления → профиль) → сайдбар → контент. Перед топбаром — ссылка «К содержимому» [TODO] предложение; в макете её нет.
- **Ctrl + \ и Ctrl + K** (`key`): Сворачивание сайдбара и поиск: глобальные сочетания; в справке продукта их стоит перечислить.
- **Фокус при смене страницы** (`focus`): [TODO] в макете не определён: предложение — после перехода фокус на заголовок страницы или на первую крошку, прокрутка вверх (как в макете), объявление названия через aria-live.
- **Панели list-detail** (`aria`): Каждая панель — region с aria-label («Список», «Деталь», «Свойства»); выбранная строка списка — aria-current или aria-selected. При ≤ 900 px панели идут по порядку DOM.
- **prefers-reduced-motion** (`motion`): Сворачивание сайдбара в rail и перестройка колонок — мгновенно; загрузочный знак вращается медленнее.
- **Контраст границ панелей** (`contrast`): Линии --divider (1,3:1) разделяют зоны, но не несут смысла; смысл — в заголовках и отступах. У карточек рамка --border 1,7:1.

## Хореография

### Сворачивание сайдбара: что делает страница (`rail`, origin: mockup)

- **Триггер:** кнопка у бренда, Ctrl+\ или клик по значку группы в rail

| at, мс | dur, мс | Что происходит | prop | easing |
| --- | --- | --- | --- | --- |
| 0 | 300 | Колонка оболочки `auto`: бренд и сайдбар сужаются 248 → 56 px. | width | --glide |
| 0 | 300 | Контент забирает освободившуюся ширину: колонка `minmax(0,1fr)` пересчитывается в каждом кадре, паттерн перестраивается (таблица шире, карточки те же 340). | layout | --glide |
| 0 | 200 | Внутри сайдбара: логотип гаснет, знак проявляется, пункты свёрнуты (подробно — на странице Sidebar). | opacity, grid-template-rows | --dur |
| 300 | 0 | Топбар не двигается: у него своя сетка, крошки получают больше места. | — | — |

- **Фокус:** Остаётся на кнопке сворачивания; страница ничего не фокусирует сама.

- **Reduced motion:** Ширина меняется мгновенно; контент перестраивается один раз.

- **Соседи:** Всё, что в контенте шириной в `1fr`, растёт (таблицы, графики, панель деталей). Блоки с фиксированной шириной (340, 300, 220) остаются прежними. Графики и таблицы пересчитывают размер через ResizeObserver [TODO] проверить в ui-kit, что нет перерисовки на каждом кадре.

### Перестройка по брейкпоинтам (`breakpoints`, origin: mockup)

- **Триггер:** окно сузилось ниже 1280 / 1180 / 900 / 760 px

| at, мс | dur, мс | Что происходит | prop | easing |
| --- | --- | --- | --- | --- |
| 0 | 0 | ≤ 1280: у list-detail пропадает третья панель; ряды настроек и подключений уходят в 2 колонки. | grid-template-columns | — |
| 0 | 0 | ≤ 1180: split cargo и все блоки дашборда становятся span 12; KPI cargo 4 → 2 колонки. | grid-column | — |
| 0 | 0 | ≤ 900: панели list-detail идут друг под другом, навигация настроек над формой. | grid-template-columns | — |
| 0 | 0 | ≤ 760: сайдбар и бренд пропадают, у топбара остаётся `1fr auto`. | display | — |

- **Фокус:** Не затрагивается; скрытые панели из порядка Tab должны выпадать (display: none).

- **Reduced motion:** Не затрагивается: переходов нет, перестройка мгновенная.

- **Соседи:** Скрытые блоки не оставляют пустого места: соседние занимают свободную ширину. Порядок в DOM = порядок при колонке (список, деталь, свойства).

### Загрузка страницы (`load`, origin: mockup)

- **Триггер:** переход на страницу, данные ещё грузятся

| at, мс | dur, мс | Что происходит | prop | easing |
| --- | --- | --- | --- | --- |
| 0 | 0 | Оболочка (бренд, топбар, сайдбар) остаётся на месте; в области контента загрузчик со знаком и подписью по центру. | content | — |
| 1600 | 0 | Данные пришли: паттерн страницы встаёт на место (раскладка уже известна, размеры не прыгают). | content | — |
| 1600 | 260 | Полноэкранный загрузчик (только первый вход): затухание 260 мс и удаление. [TODO] для обычных переходов в макете загрузчик на всю страницу не используется, а затухания области нет: предложение — Skeleton формы паттерна. | opacity | ease |

- **Фокус:** На время загрузки остаётся на элементе, вызвавшем переход; после — по правилам страницы (заголовок или первая крошка).

- **Reduced motion:** Знак вращается в три раза медленнее; затухание без перехода.

- **Соседи:** Сайдбар и топбар не перерисовываются; активный пункт и крошки меняются сразу при переходе, не при загрузке данных.

## Дополнительно

### Как не оставить мёртвого места

- Ряд в 12 колонок: сумма span равна 12 (3+3+3+3, 8+4, 5+4+3). Ряд из 9 или 10 колонок оставляет дыру справа. Блоков, которых не хватает до 12, растягивайте, а не оставляйте пустыми.
- Карточки одного ряда одной высоты: `align-items: stretch`, высоту диктует самая высокая. Низкая карточка не «висит» над пустотой: контент в ней растёт или внизу появляется «Все →».
- Стопка рядом с таблицей: правая колонка — flex-колонка на всю высоту, последняя карточка с `flex: 1`: она заполняет остаток, а не обрывается посередине.
- Панели во весь экран: список–деталь занимает `100vh − 56 − 32`, у каждой панели `min-height: 0` и `overflow: auto`. Прокручивается панель, не страница: нет двойного скролла и пустой подложки под короткой панелью.
- Короткое содержимое: пусто — это состояние (EmptyState по центру), а не пустое место. Блок не растягивают ради вида.
- Ширина настроек: колонка до 1080 px слева от свободного поля. [TODO] на экранах шире 1600 справа остаётся пустота: решить, центрировать колонку или добавить правую панель подсказок.
- Липкие панели (сайдбар, навигация настроек, панель сохранения) не создают пустых зон: они в потоке и прилипают, а не вырезают колонку.

## Как использовать

Импорт: в ките — `import { AppShell } from "@/ui"`, в приложении — `import { AppShell } from "@astronaut/ui-kit"` (нужен `@astronaut/ui-kit/styles.css`).

<!-- manual:start -->
Компонент: `AppShell`. Типы: `AppShellProps`, `AppShellContentProps`. Без бизнес-логики и без роутера: области заполняются тем, что вы передали.

```tsx
import { AppShell } from "@/ui";
```

Пропсы `AppShell` (плюс атрибуты `<div>`, `ref`, `style`; высоту задаёт родитель или `style`/`className`, например `height: 100dvh`):

| Проп           | Тип                    | По умолчанию | Описание                                                                                              |
| -------------- | ---------------------- | ------------ | ----------------------------------------------------------------------------------------------------- |
| `brand`        | `ReactNode`            | нет          | Ячейка бренда над сайдбаром (248 или 56 px, высота топбара). Без неё сайдбар занимает обе строки.     |
| `sidebar`      | `ReactNode`            | нет          | Ячейка слева; обычно `Sidebar`.                                                                       |
| `topbar`       | `ReactNode`            | нет          | Ячейка сверху; обычно `Topbar`.                                                                       |
| `rail`         | `boolean`              | нет          | Сужает ячейки бренда и сайдбара до 56 px; передавайте то же значение, что и сайдбару.                 |
| `narrow`       | `boolean`              | нет          | Принудительно скрывает бренд и сайдбар (узкий вид).                                                   |
| `responsive`   | `boolean`              | `true`       | Скрывать бренд и сайдбар, когда ширина оболочки ≤ 760 px (container query).                           |
| `contentProps` | атрибуты `<main>`      | нет          | `id` (для ссылки «К содержимому»), `className`, `aria-busy`, `data-*` области контента.               |
| `children`     | `ReactNode`            | нет          | Содержимое области страницы (`<main>`): поля 16 px, прокручивается само.                              |

```tsx
<AppShell
  style={{ height: "100dvh" }}
  rail={rail}
  sidebar={<Sidebar rail={rail} onRailChange={setRail} groups={groups} brand={<Logo />} brandMark={<LogoMark />} />}
  topbar={<Topbar crumbs={crumbs} search={<TopbarSearch />} actions={actions} />}
  contentProps={{ id: "content" }}
>
  <CargoPage />
</AppShell>

<AppShell brand={<Logo />} sidebar={<MyMenu />} topbar={<MyHeader />} responsive={false}>
  …
</AppShell>
```

Доступность:

- Контент в `<main>` (одна область-landmark на странице); сайдбар и топбар приносят свои `<aside>`, `<nav>`, `<header>`. Дайте `contentProps.id` и добавьте над оболочкой ссылку «К содержимому».
- В узком виде бренд и сайдбар скрыты (`display: none`): навигацию для телефона делайте отдельно (например, через Sheet).
- Контейнер оболочки — `container-type: inline-size`: `position: fixed` потомки позиционируются относительно оболочки; для оверлеев используйте портал в `body`.
- Анимация ширины 300 мс отключается при `prefers-reduced-motion`.
