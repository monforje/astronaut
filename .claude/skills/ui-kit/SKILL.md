# UI-кит Astronaut

Кит лежит в `frontend/ui-kit`: у каждого компонента спецификация (варианты, состояния, правила, доступность, токены, хореография) и, если компонент реализован, настоящий код в `@/ui`. Агент берёт готовое, а не изобретает своё.

## Порядок работы

1. **Найти.** MCP-сервер `astronaut-ui-kit` (`.mcp.json` в корне репозитория): `search` («таблица грузов», «тост») или `list_components` (по группе). Нет MCP — читать `frontend/ui-kit/src/generated/llms.txt` (список) и `src/entries/<id>/README.md`.
2. **Прочитать до использования.** `get_component {id}`: «Как использовать» (импорт, примеры), пропсы, доступность. Нужны состояния, варианты, правила, токены или движение: `sections: ["states", "variants", "rules", "tokens", "choreography"]` или `["all"]`. Движение отдельно: `get_choreography {id}`.
3. **Понять реализацию** (если пропсов в README мало): `get_component_source {id}`.
4. **Импортировать из кита:** `import { Button } from "@/ui"`. Статус компонента в ответе: `реализован` — можно импортировать; `только спецификация` и `запланирован` — в `@/ui` его нет.
5. **Токены и правила:** `get_tokens` (цвета ролями, радиусы, размеры, слои состояний, тени), `get_design_rules` (общие правила; `topic` сужает).

Если MCP недоступен: `frontend/ui-kit/src/docgen/design-rules.md` (правила), `src/styles/tokens.css` (токены).

## Правила (полный список — `get_design_rules`)

- Цвета только ролями из `tokens.css` (`var(--text)`, `var(--primary)`), без HEX; длительности токенами `--dur-f/--dur/--dur-s`.
- Нет левых акцентных линий у карточек, алертов и строк.
- Цифры, суммы и идентификаторы без моно (Onest с `tabular-nums`); Fira Code только для кода и логов.
- Две кнопки в карточке или панели: 50/50, главная слева; одна главная (primary) на экране.
- Dialog без крестика: «нет» слева, «да» справа.
- Аватары плоские: без 3D и градиентов.
- Анимации бренда только готовые из `brand/animated`; свои не рисовать.
- Контраст текста не ниже 4,5:1, смысл не только цветом.

## Чего не делать

- Не копировать стили, классы и разметку из `frontend/landing` и `frontend/demo-site`: образец — кит, а не лендинг.
- Не писать свою кнопку, поле, таблицу, диалог, тост, если такая запись есть в ките (`search` сначала).
- Не писать HEX, `style=""` с цветами, самодельные иконки и спиннеры: иконки через `Icon`, загрузка через `loading`/`Spinner` кита.
- Не выдумывать пропсы и варианты: только из README и исходников.

## Нужного компонента нет

Не изобретать. Варианты по порядку:

1. Записать потребность в `[TODO]` рядом с кодом (что нужно, на каком экране) и использовать ближайший реализованный компонент из кита.
2. Предложить пользователю добавить запись в кит. Шаги (подробности в `frontend/ui-kit/CLAUDE.md`, разделы «Как добавить компонент» и «Реализация компонентов»): `src/entries/<id>/` с `doc.tsx`, `<имя>.css` (классы с префиксом), `demo.tsx`; реализация `Name.tsx` + `index.ts` и строка `export * from "../entries/<id>"` в `src/ui/index.ts`; `Name.test.tsx`; `task bun -- run docs`; `task bun -- run verify`. В кит правки вносить только по просьбе пользователя.
